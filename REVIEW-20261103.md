# Core review, 2026-11-03

A review of the emulator's core (`core/src`, ~48k lines) for correctness defects and performance opportunities, in
eight areas, each read statically and verified wherever a cloud session allowed: the reference interpreter and CPU
state; the block interpreter, the FP core and crypto; the JIT's integer emitter; its FP and SIMD emitters; the JIT's
runtime (dispatch, caches, invalidation); the MMU, memory, snapshots and lz; the platform (run loop, parallel SMP,
GICv3, timers, the exported ABI, the small devices); virtio and the xHCI.

Every correctness finding is fixed (the table at the end), and the fixes have had the dev VM's CI (§1).
**This file is now what's left**: the performance opportunities P6 and P7 (P1-P5 are done) and the two runs §1 still
lists.

**Verification labels.** *Confirmed (test)*: a test shows the defect. *Plausible*: argued from the code, not shown by
a run, with the reason. The review's own verification files lived in the session's scratchpad and are gone; each
item says what its test did, so it can be written again (most are a page of Rust against the `pub` modules).

## 3. Performance opportunities

None is measured in Chromium: each needs `bench/run.ts`'s A/B on the dev VM (docs/benchmarking.md "Rules") before a
number is claimed. Ranked by the likely gain on the long workloads; each says what to measure first.

### P1. Done

The nG list's overflow flushed the whole TLB: now a scan of nG marks (2026-11-04, the table in §5;
`bench/boot/REPORT.md` "Past the nG list").

### P2. Done

Vector FCVTL/FCVTN sent zero and infinite lanes, and widening with IXC clear, to the helper: now the scalar FCVT's
rule lane by lane (2026-11-04, the table in §5). Not measured: no workload's helper counts were taken first, and the
inline paths cost no more lane ops than before (FCVTL one compare where it had three; FCVTN one reduction fewer, a
compare and a shuffle more).

### P3. Done

Structure loads and stores in the interpreters were one bus access an element (64 for `ld1 {v0.16b-v3.16b}`): now the
whole transfer through `Bus::fast` when it's RAM in one page, 8 bytes an access with the elements (de-)interleaved in
a buffer (2026-11-04, the table in §5; docs/cpu.md "The structure loads and stores"). Natively (release, flat bus):
`ld1 {v0-v3}.16b` 207 → 15 ns, `st1` 281 → 15, `ld4 .16b` 183 → 22, `st4` 271 → 20, `ld2 .8h` 100 → 18
(`ldp q0, q1` 11). In Chromium it cost the reference interpreter a call per instruction (the FP guest −28%):
LLVM stopped inlining `exec` into the step loop. Fixed with P4 (`exec` called directly, the AdvSIMD handler lookup
and `extend` always inlined); against the base the user-facing benchmarks are flat and `interp_mips` −1.1%
(`bench/interp/REPORT.md` "REVIEW P3 and P4").

### P4. Done

The interpreter's FP fast paths (add, sub, mul, div, sqrt, single and double) skip the exactness test when FPSR.IXC
is already set (2026-11-04, the table in §5): the FP guest +3.5-3.9% (`interp_fp_mips`, `bench/interp/REPORT.md`
"REVIEW P3 and P4").

### P5. Done

The five smaller JIT items (2026-11-04, the table in §5; `bench/interp/REPORT.md` "REVIEW P5"): ADRP is the entry PC
plus a constant (`Func::page`: a VA keeps its PA's page offset, region members in other pages included, as `pc_plus`
already assumed); BR/BLR/RET leave their target in ADDR for `indirect` (V8 doesn't forward the store: CoreMark's hot
code reloads the PC 87 times, from 97); vector FMAX/FMIN/FMAXNM/FMINNM test the result for NaN lanes, and under FZ
both operands for denormals in one branch; the emulated double FMA shuffles a by-element factor once for the product
and once for the guard (TurboFan had five `dup`s an instruction, now two: V8 doesn't merge them); `Cache::invalidate`
gives the tables and the pending batch the dropped keys once (deduplicated), and `PageIndex::file` files a key once.
In Chromium, against the base, alternated: CoreMark +1.5% and Alpine's Lua phase −1.7 to −2.4% time, the rest within
noise (llvmpipe flat in a session of its own). Not measured: `Cache::invalidate` alone (no workload's IC rate showed
in a profile), the emulated FMA on a host without fused `madd` (the dev VM fuses).

### P6. TLBI by VA scans the whole TLB while a 1 GiB block of that half is live

`flush_va` (`core/src/mmu.rs:350-367`): with any 1 GiB-block entry of the VA's half live, a TLBI scans 16,384 indices
× 8 slots (131K checks); with 2 MiB blocks, 4K checks (near-permanent in the high half, where the kernel's 2 MiB
mappings live). The backlog's "a TLBI by VA a 16 KiB scan" covers the transfer-cache part only. Measure the time in
`flush_va` in a profile of a TLBI-heavy workload (Firefox, munmap-heavy userspace) first.

### P7. The round-robin loop reads the clock twice an iteration

`xhci_tick` calls `self.ns()` before checking there's an xHCI, then `lines()` calls `now()`: in realtime a host
`now_ms` call an iteration. Round-robin isn't the page's path; only if Node's runs matter.

## 4. Notes for the docs and the backlog (when they're moved there)

- **Backlog ratings:** no item was found misrated with evidence. Rated right on inspection: the MMU-off Device
  alignment, LSE and exclusives on Device memory, the TLBs a restore empties, "A restored machine's lost interrupt"
  (no static cause in the GIC or the run loop's restore), "An exit's remaining cost" (a SeqCst fence an iteration even
  with no ASID change), "Reserved AdvSIMD encodings with FPEN 0" (harmless; the same order applies to scalar FP16's
  `ftype` and the by-element forms' reserved sizes, equally harmless: worth a word), the reference interpreter's
  role, the single FMA's midpoint test, `relaxed_trunc` for FCVTZS, the core without `simd128` (the JIT's modules use
  SIMD128 and only `madd`/`nmadd` of relaxed SIMD), the Liftoff zero-fill, the helpers left for MSRs, the xHCI's IMOD,
  Stop Endpoint's window, isochronous transfers, the console without input, and "a vCPU that slept through more than
  `HELD_MAX`".
- **"Corpus depth: thin FP flag paths"** is about right: a biased fuzz against qemu-aarch64 (1.07M FP and AdvSIMD FP
  instructions, every FZ/DN/RMode, the IOC/DZC/OFC/UFC/IXC/IDC paths) found nothing; its generator (biased special
  values per lane size, random FPCR) is the "biased forms" that item asks for.
- **docs/testing.md could say:** natively `wait()` sleeps at most 50 µs whatever the wake word says, so lost-wake-up
  races are invisible to the native parallel tests; only the Chromium ones can catch them.
- **An oracle caveat:** QEMU 8.2's FJCVTZS with FPCR.FZ = 1 and a positive denormal input sets Z (`1e7e0061`, d3 =
  0x000000047971f7f2, FPCR = 0x1c00000: QEMU Z = 1, webpc Z = 0). The Arm pseudocode (`FPToFixedJS`: Z only for an
  exact conversion of a value whose fraction is all zero) and the M4's corpus (`jscvt.fjcvtzs.0373`) agree with
  webpc: mind it when qemu is the FP oracle.

## 6. Checked and found clean

- **Interpreter semantics:** every corpus generator's forms with new salts at 2-3× the counts against qemu-aarch64
  (~150k tests): differences only where QEMU is known to differ (MTE's SUBG/STGP, its 512-byte DC ZVA, the FJCVTZS
  case above, si_code 2 against 1). Every a64.inc pattern filled with random fields (400 words each, EL0 and EL1):
  none reached `Exit::Unimplemented` (which stops the VM, and core/fuzz's sweep skips). Read against the Arm ARM:
  SP/XZR, bitfields and EXTR, SDIV by -1, CRC32, conditional compare, FlagM/FlagM2, load/store UNDEFINED rules,
  exclusives' alignment and monitor order, CASP pairs, structure lane math, AdvSIMDExpandImm/VFPExpandImm, EL0 trap
  controls, timer TVAL/CTL/ISTATUS, TLBI and AT decoding, syndromes, FAR, vector offsets, SP banking, illegal ERET, DIT
  and SS on entry and return, the ID registers against the features.
- **FP core, block interpreter, crypto:** a qemu-aarch64 harness (an RWX page, a SIGILL/SIGSEGV handler) against
  `interp::run` on biased FP inputs and random FPCR: scalar and AdvSIMD FP (FRECPE/FRSQRTE/FRECPS, FCVT*, FRINT*,
  FMAX/FMAXNM, FMA, FCVTXN, fixed point) 600k + 470k mixed with integer AdvSIMD; crypto (AES, SHA1/256, SHA512/SHA3,
  PMULL 8/64, CRC32/C) 200k; no mismatch but the FJCVTZS caveat. Encodings webpc treats as UNDEFINED, run on qemu
  `-cpu cortex-a72` (v8.0 + crypto): qemu ran none (nothing of v8.0 missing). Not covered: x8 and up, Rd/Rn = 31,
  FZ16. By reading: the block interpreter's decode fallbacks, Rd/Rn = 31, `pack` layouts, `hot`'s exclusives, LSE/CAS
  with Rt/Rs = 31, the FPEN check, chaining and `rest` accounting, the PC and steps when an exit comes mid-block.
- **JIT integer emitter:** the differential test at 30,000 words a class (10× the default) through the conditional,
  add/sub, logical, bitfield, extract and shift classes before its timeout; a new MMU-on fuzzer (an interpreter VM
  against one compiling on sight, 4 KiB pages of mixed permissions, EL1h and EL0, groups off one base, SP bases,
  LDTR/STTR, SIMD single and pair, register offsets, exclusives and pairs, acquire/release, LSE and CAS, flags, MRS
  NZCV, DC ZVA, the monitor armed at random; each state twice so the second run hits the TLB; whole `Cpu`, data pages
  and steps compared): 9 seeds × 7000 sequences clean, and one page's permissions flipped on the JIT side was caught
  (108 of 500 differed). By reading: carries from lazy flags, the condition table, 32-bit zero extension, SP/XZR,
  failure chains' `written` masks, groups, exclusives and the pair-lock index, the TLB path's page crossing and wrap,
  LDTR/STTR's arrays, Device pages missing the fast path, DC ZVA's DZE guard, step accounting; no guest-reachable
  panic.
- **JIT FP and SIMD emitters:** the differential test at 16,384 words a class over the integer NEON and FP classes,
  both FMA arms (relaxed `madd` fuses on the x86_64 host); FRECPE/FRSQRTE/FRECPX exhaustively (every 9-bit table
  input, both exponent parities, single and double, FZ on and off, scalar and vector: 155,648 runs, no difference).
  By reading: FPOK/FZOK's computation and rollback, result-exponent tests, zero clauses, no wasm NaN ever stored,
  FMIN/FMAX's zero order, FCMP/FCMPE, `to_odd`, the fused and emulated FMAs, conversions and rounding, upper-half
  zeroing, dirty-local flushing before helpers, the integer NEON saturations, crypto's fusions.
- **JIT runtime:** the keys (PA | EL | MMU), cross-page edges, transfer-cache generations, epochs and slots, the
  compile worker's `seq`/`ready` wrap, `done` reordering, `ival_log` trimming, compile against IC under the lock,

- **MMU, memory, snapshots, lz:** a randomized TLB-against-a-fresh-walk test (39 seeds × 4000 operations: both halves,
