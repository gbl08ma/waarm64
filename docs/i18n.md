# The page's words (i18n)

Every word the user reads comes from one catalog, `web/messages/en/`, through **i18next**: the page, its dialogs and
errors, and the words the page puts in the guest (its units' descriptions). The point is copy that can be reviewed and
changed in one place, by area ([copy.md](copy.md) says how they're written), each message with a note that says where and how it's shown; translations would be
another directory beside `en/`, read at load (a change of language takes a reload). Developer-facing text stays where
it is: logs, the console, URL parameters, `npm start` and the tools, the serial console, the emulator's own diagnostics.

## The catalog

One JSON file per area (`common`, `machine`, `toolbar`, `statusbar`, `machines`, `disks`, `snapshots`, `network`, `osk`, `usb`,
`folders`, `sound`, `display`, `clipboard`, `guest`), listed in `web/messages/en/index.ts`. Each entry:

```json
"Snapshots.restore": {
  "message": "Restore",
  "note": "Button on each snapshot kept with the machine (Machines page, Snapshots tab): the machine as it was when the snapshot was taken."
}
```

- **The key is `<Source>.<name>`**: `Source` is the stem of the file that uses it (`Snapshots.svelte` → `Snapshots`,
  `ask.svelte.ts` → `ask`, `qcow2-write.ts` → `qcow2-write`), `name` says which element (`restore`, `restore.title`,
  `diskInUse`). Code names it in full with its area, `snapshots:Snapshots.restore`. A message used from two files is
  keyed by the one that renders it.
- **The note** says where the words are shown (screen, tab, menu, dialog, message bar, tooltip, guest), what kind of
  element they are (button, title, error headline, detail), when, and what each `{{parameter}}` is.
- **Parameters** are `{{name}}`. `{{when}}` given a `Date` is written as the browser's locale writes dates (as
  `toLocaleString()`), `{{when, date}}` its date alone (`toLocaleDateString()`); `{{size, bytes}}` a byte count in KiB, MiB or GiB (`web/app/bytes.ts`); a list is joined with
  commas, `{{items, lines}}` one per line; a parameter that is a message (`Msg`) is rendered in its place.
- **Plurals** are i18next's: `Source.disks_one` and `Source.disks_other`, used with a `count` parameter.
- **Markers** wrap words the page draws differently (a button, a link, bold): `"Open <open>Open disk…</open> to start"`.
  A component renders such a message with `<T k="…" params={…}>` and a snippet per marker (`web/app/T.svelte`); `plain()`
  drops them where only text fits (a tooltip).
- **References** say another entry's words in place, with i18next's nesting: `$t(common:product.name)`. They're for
  fixed words said in many messages, the product's name above all (`common:product.name`, written once;
  [copy.md](copy.md) "Words"). A reference names a whole entry, without options, parameters or plural forms; an entry
  that messages reference needs no source of its own. The tools and tests that read the catalog take its words with
  the references resolved (`expand`, web/messages/en/index.ts), as the page renders them; the copy editor shows a
  message's words with its references as written.
- Words are whole sentences: a message isn't assembled from fragments. A sentence that varies is a message per variant,
  or a message whose parameter is another message.

## In the code

`web/msg.ts` is for any code (the page, workers, libraries, Node): it describes what to say and imports nothing.
`web/i18n.ts` is the page's alone: it renders.

- A component: `{t('snapshots:Snapshots.restore')}`, `title={t('…')}`, `<T k="…">` for markers.
- The page's code: `t(key, params)` for words, `ask.confirm(t(…), { title: t(…), ok: t(…) })`, `setState(state, msg(…))`
  or an error (`notify`, `setState` take words, a `Msg` or an error).
- **Errors** the user may read are `MsgError(key, params, { cause })`: the key is the headline, the cause its details
  (the message bar shows the headline and, under it, the causes, one per line: `describe()`). "X couldn't be done:
  <why>" is `new MsgError('…couldn't be done', …, { cause: why })`, never words joined with colons, nor a headline and
  a second line in one message: the line is a cause of its own (`{ cause: new MsgError('….cause', …) }`, keyed by the
  headline's key and `.cause`, or by what it says when causes are shared, `disks:disk-actions.inUse`), and a list of them is a
  chain (`causes(list)`, web/msg.ts). An `Error` with
  plain words is a developer's (an invariant, a protocol slip, a log): if it reaches the page, its words are details.
  Logic never matches an error's words: it checks a field (`problem`) or the message's key (`msgOf(e)?.key`).
- **Workers render nothing**: they throw `MsgError`s or post `Msg`s with all the data the words need, and post errors
  as `toWire(err)`; the page takes them back with `fromWire` (or `describe`, which takes either). What the page puts in
  the guest is rendered by the page and sent with the start (`web/app/guest-words.ts`).
- **The Rust core and the C code build no words**: they return codes (a restore's `snapshot::Error`, an allocation's
  failure), and the page maps each code to a key. A panic's text is a diagnostic: shown as details.

## Checks

`node tools/i18n-check.ts` (in `scripts/ci.sh`) checks what TypeScript can't:
- every entry has its words and a note, every reference (`$t(…)`) names an entry with fixed words and resolves, every key the code names exists and is a literal (a map from a code to its
  keys, if need be), every entry is named, by the file its key says;
- **no error is written as one message**: words that are a headline (a first line with words of its own and no
  period, question mark, colon or ellipsis) and a line under it after `\n` are flagged; the headline is a message, the
  line a cause of its own (`new MsgError(headline, …, { cause: new MsgError(…) })`). A first line that is only a
  parameter (a tooltip's `{{name}}\n{{about}}`) or a sentence (a notice's second paragraph) isn't a headline;
- a call that names a key (`t`, `msg`, `new MsgError`, an `Error` subclass, `<T k params>`) gives exactly the
  parameters its words use, for every key it may name: a literal, a conditional's or `??`'s keys, or keys through a map
  or a constant of the file (`t(STATE_WORDS[s])`, `const [key, tone] = PHASE_WORD[p] ?? ['', …]`, a constant found by
  its scope); and parameters as an object (its spreads followed), a conditional's objects (paired with the key's when
  the same condition picks both), a constant of the file, or `undefined` (none). A key or parameters that come from a
  function's parameter or another module aren't checked;
- no words outside the catalog in `web/`: in a component's markup and copy attributes (`title`, `aria-label`,
  `placeholder`, …), as the string results of a markup expression, in copy properties (`label: '…'`, `title`, `text`,
  …) and as sentence-like strings in the code: one that starts with a capital and has three words or more (a `;` in
  it joining clauses of prose, not declarations like CSS's), the value after a `Field=` (a unit's line), and one in
  lower case of four words or more, of letters, that ends as a sentence (`.`, `?`, `!`, `…`) and has two common words
  (an article, a verb, a preposition) among them. A developer's phrase in lower case without a sentence's end, the
  renderers' diagnostics among them, isn't flagged: in the code it reads like a message, and copy ends with a period.
  A line with `i18n-ignore` (or after one with `i18n-ignore-next`) is skipped: a command, a file name, a format's
  name, a developer's words;
- **no caught error's `.message` is shown** in `web/`: a `MsgError`'s `message` is its developer text (its key and
  parameters), so the page says an error with `describe`, `errorText` or `msgOf`. A `catch`'s error, or a rejection
  handler's (`.catch(fn)`, `.then(_, fn)`), whose `.message` (through `String`, a template, `??`, a conditional)
  reaches a call that shows words (`notify`, `setState`, `ask.*`, …), a message's parameter, the DOM's words or `ui.*`,
  or a component's state shown in its markup, is flagged; `msgOf(e) ?? e.message` (a message first) isn't;
- no worker reaches `web/i18n.ts` or i18next (the import graph from each `new Worker(new URL(…))` and worklet);
- the docs quote the page as `[Open disk…](ui:machine:power-actions.openDisk)`, and the words must be the catalog's (`--fix-docs`
  rewrites them after a change of words); a bold, italic or double-quoted phrase that is a message's words (two words
  or more, or ending in "…") must be written as such a quote. Either may be broken across two lines (a paragraph's
  wrap);
- no test writes out the page's words (`tests/`): a string, template or regex literal that is a message's words from
  its start (two words or more), four words or more from its middle, or a title-case one-word message whole
  (`'Retry'`). Lower-case words and acronyms (most often a state's value), test names, assertions' messages, logs and
  `Error`s aren't read; a test named `wording: …` is skipped, and a line with `i18n-ignore` (data that reads like a
  message, such as a Tailscale peer's `'Running'`).

## Editing the copy on the page

The copy can be changed where it's shown, then written back into the catalog. In the browser's console:

- `copyEdit.start()` turns the editor on for this tab (a reload). While it's on, `text()` and `marked()` (web/i18n.ts)
  start every message's words with an invisible mark (U+2063, the message's number in U+200B/U+200C, U+2064), and
  web/app/copy-edit-ui.ts, loaded only then, takes the marks out of the page's text and its words' attributes (`title`,
  `aria-label`, `placeholder`, …) as they appear (a `MutationObserver`), remembering which message each piece of text
  is. Elements that show a message get a dashed outline.
- **Alt+click** opens a panel with the messages of what was clicked (the nearest element that shows some, its tooltips
  included): each entry's key, note and words, with the plural forms of a counted one. Saving shows the new words at
  once where they're plain text (a message with markers, from `T.svelte`, shows them when it's drawn again, or after
  a reload), and the panel flags a parameter or marker lost or added. The changes are kept in this browser
  (`localStorage`) and stand in for the catalog's words on every load while the editor is on.
- `copyEdit.dump()` gives the changes, `{ "ns:Source.name": "words" }` (copied to the clipboard too), and
  `node tools/copy-apply.ts changes.json` writes them into `web/messages/en/` (notes untouched), then
  `node tools/i18n-check.ts --fix-docs` brings the docs' quotes up to them. `copyEdit.stop()` turns the editor off
  (the changes are kept), `copyEdit.clear()` forgets them.

Only what can be brought on screen can be edited this way (a rare error or the guest's words are edited in the
JSON). The marks are in the words for that load only: code that compares rendered words compares marked ones
alike, and the words the page sends the guest are taken out of them (`unmarked`, web/app/guest-words.ts). Off, the
editor costs a flag's check per message. `tests/page-copy-edit.test.ts` tests it in Chromium.

## Tests

Tests don't depend on the words: they take them from the catalog, `t(key, params)` (web/i18n.ts, which runs in Node)
for a message whole and `words(key, params)` (tests/words.ts) for a pattern of one whose other parameters may be
anything, or check a key or an element. A change of words changes no test. A test that must pin words in a place on
purpose is its own case, named `wording: …`, and only there may it write them out. `tests/i18n.test.ts` tests the
renderer and the checks.
