# Decisions

The choices that bind the whole project. Changing one is the user's call, and the change updates this page and the
doc it affects in the same commit. A topic's own binding choices are in its doc (e.g. [graphics.md](graphics.md)
"Decisions"); how each works is in the docs [by topic](README.md).

| Area | Decision |
|---|---|
| Guest ISA | ARMv8.0-A AArch64 with FP and AdvSIMD, no AArch32; LSE atomics and CRC32; the crypto extensions (AES, PMULL, SHA1, SHA256) switchable and on by default, and so are FEAT_SHA512, SHA3, RNG, E0PD, JSCVT, LRCPC, LRCPC2, SB, FlagM, DIT, FRINTTS, DotProd and RDM. No SVE/SME, PAC, BTI or MTE (their hint-space encodings are NOPs). **An optional extension is advertised unless a measurement on the programs that use it shows it slower than what guests do without it; a tie is advertised. One that loses stays implemented, unadvertised, for software that assumes it (the user, 2026-11-02): FEAT_I8MM since 2026-11-10 (off by default, `?i8mm=1`; its int8 matrix kernels 19% slower), FEAT_FCMA since 2026-11-10 (off by default, `?fcma=1`; its by-element and FCADD kernels 10% and 3% slower), FEAT_FP16 and FEAT_FHM since 2026-11-10 (off by default, `?fp16=1`, `?fhm=1`; a half GEMM tile 2.05× and FMLAL's by element 35% slower, a half axpy 27% and FMLAL by vector 17% faster), FEAT_BF16 since 2026-11-10 (off by default, `?bf16=1`; BFDOT's dot product 1.48× and BFMMLA's GEMM tile 2.61× slower, BFMLAL level).** ([docs/cpu.md](cpu.md)) |
| Privilege | EL0 and EL1 only. No EL2/EL3, no secure state |
| MMU | Stage 1 only, 4K granule, 48-bit VA, TTBR0/TTBR1, ASIDs, software-managed access flag |
| Platform | QEMU `virt`'s memory map; **GICv3 (no ITS) since M7** (the GICv2 model was dropped in M7: every guest we run has a GICv3 driver); generic timer, PL011, a PL031 RTC (realtime mode), PSCI over HVC (answered in the core, CPU_ON included; SYSTEM_OFF/RESET exit to the host), virtio-mmio v2, a DTB generated from the VM config ([docs/platform.md](platform.md)) |
| Boot | Direct kernel boot (arm64 `Image` + initrd + DTB) for the tests' guests; users' images through UEFI (below) |
| Core | Rust compiled to wasm32 (the same crate builds natively for tests); host glue in TypeScript without a build step |
| Guest memory | **Layout A** (M0.5): one shared wasm32 memory, core state then guest RAM (≤ ~3.5 GiB). One lowering point for guest accesses in generated code; TLB tag bits 3–11 hold a memory index: RAM past memory 0 goes to spill memories, NUMA nodes for the guest ([docs/spill-memories.md](spill-memories.md)) ([docs/architecture.md](architecture.md)) |
| JIT | Gadget style (inline what pays, helper calls into the interpreter's code for the rest), blocks keyed by guest PA, loop regions with tier-up, exact step accounting (but **in parallel SMP, compiled code has no step budget**: it polls a per-vCPU stop word where a cycle can close, and chunks may run past their steps to the next poll; round-robin, deterministic or realtime, keeps the counted code and `tests/steps.txt` unchanged: the user, 2026-11-16; [docs/jit.md](jit.md) "Preemption"), one code cache of 320 MiB of wasm flushed whole when full ([docs/jit.md](jit.md)); what isn't compiled runs in the block interpreter, the same blocks decoded once into micro-ops ([docs/cpu.md](cpu.md) "The block interpreter") |
| Determinism | Deterministic mode (time from steps) for tests and most benchmarks: every guest takes the same steps on every host and tier. Realtime mode for guest-timed work and interactive use |
| SMP | N vCPUs, one core, two modes: **deterministic round-robin** on one thread (tests; exact steps; virtual time = the steps of all vCPUs) and **parallel**, a worker per vCPU with its own core instance and function table, on one code cache the vCPUs share (each module compiled once; [docs/jit.md](jit.md) "Sharing") (users, scaling; realtime only). `TLBI …IS` completes before the issuer's `DSB` returns; `IC` drops the code from the shared cache at once, and each vCPU's table catches up before its next block; DMB is a real fence in parallel JIT code; the core's guest-RAM accesses are atomics ([docs/platform.md](platform.md), [docs/cpu.md](cpu.md)) |
| Devices | Backends in TypeScript in one device worker; the core owns the virtio rings; net is raw Ethernet frames ([docs/devices.md](devices.md)) |
| Browsers | Chromium first; cross-origin isolation required |
| License | MIT. GPL/EPL/CeCILL projects are oracles, guest workloads or behavioral references only, never copied (`THIRD_PARTY.json`) |
| The page | **One machine per page**, under the JIT, realtime, parallel SMP. **The page starts no disk image** (since 2026-10-17): its machine is EDK2 waiting for the user's disk (Open disk, a drop, `?disk=`), and it names no distribution; Debian 13 is the tests' and benchmarks' guest (`?machine=debian`). Machines are named and stored in the browser, with their disks, overlays and snapshots ([docs/machines.md](machines.md)). The screen (the framebuffer, then virtio-gpu) is the default view, with keyboard and mouse through virtio-input; a serial terminal on xterm.js is the fallback. Disks persist in OPFS copy-on-write overlays ([docs/frontend.md](frontend.md)) |
| Booting users' images | **Unmodified, through UEFI**: EDK2's ArmVirtQemuKernel (built in Podman, reproducible) entered as an `Image` through our direct boot, running the image's own bootloader (GRUB, Limine, shim). **Not** a loader in the page that reads `/boot` and guesses the boot entry (rejected: not standardized, breaks with each distro's layout, takes the choice of bootloader away). The DT stays the guests' description (ACPI measured the same; out of scope). A disk comes from a file or a URL, raw or qcow2; its changes go out as a qcow2 over the base or as a whole disk, and come back in ([docs/firmware.md](firmware.md)) |
| Frontend | **Svelte 5** for the page, the rest of `web/` plain TypeScript; **built with Vite** (the user, 2026-10-24); a desktop application's look. **`npm start`** on a fresh clone (Node, rustup and Podman the only prerequisites) builds everything the page serves (the core, the tailnet client, the firmware, the guest agent, Vulkan's renderer) and serves it; `npm run dist` makes a static copy, deployed by the user at `https://vm.tny.im` (a Cloudflare Worker with static assets); disk images on `vmdisks.tny.im`, **never R2**, whose uncached reads anyone can bill ([docs/remote-disks.md](remote-disks.md)). New runtime dependencies need the user's OK |
| The page's words | **One catalog, `web/messages/en/`, through i18next** (the user, 2026-11-02): every word the user reads, the guest's units' descriptions too, an entry with a note on where it's shown, keyed by the source that uses it; only the page renders (workers, the core and C send codes, keys and data); `tools/i18n-check.ts` checks what TypeScript can't ([docs/i18n.md](i18n.md)). Developer-facing text (logs, console, URL parameters, `npm start`) stays as it is |
| Graphics | **No software rendering or translation layers in the guest.** OpenGL ES through Mesa's upstream **virgl** onto **our virgl renderer on WebGL2** (the page's default where WebGL2 is; [docs/graphics.md](graphics.md) "Decisions"). **Vulkan** (the user, 2026-10-25): Venus translated onto WebGPU, a per-machine choice until every program that switches to it is no slower than on virgl; a C toolchain for wasm allowed ([docs/plans/graphics.md](plans/graphics.md) §2) |
| Video | VA-API over virgl, decoded by the browser's WebCodecs (not V4L2); H.264, VP9, AV1; **HEVC dropped** ([graphics.md](graphics.md) "Video") |
| Audio | virtio-snd to an AudioWorklet; sound on by default (from the first click); the microphone opened when the guest records ([docs/audio.md](audio.md)) |
| USB | WebUSB passthrough and WebHID onto an emulated xHCI, and the Gamepad API onto an emulated wired Xbox 360 controller (with rumble) for pads neither reaches; isochronous transfers left out (WebUSB protects the classes that use them) ([docs/usb.md](usb.md)) |
| Network | Raw Ethernet frames to a gateway in the page; our own tailnet client (Rust, wasm) for Tailscale and tailcat; IPv6 required; several adapters per machine on connections the browser keeps ([docs/networking/tailnet.md](networking/tailnet.md), [docs/networking/adapters.md](networking/adapters.md)) |

Deferred: SVE, EL2, 16K/64K granules (needed for RHEL-family kernels), virtio-pci/MSI, GICv3 ITS and LPIs.
