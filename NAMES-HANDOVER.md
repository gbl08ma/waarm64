  It recommends changes to kickoff decisions 4 and 12, so the track stops here for the user's decision**; no loop
  (the finding 3 build, N6) starts before it. Not a deep redesign: the rule, the registry, the agent and the page
  stay. What needs the user's answer (the document's "Decisions for the user"):
  1. *Decision 4*: servers ask an explorer once per block their registry is anchored in (one GET, in the background),
     beyond the headers of renewals they finish. Without it, a forged header at 1/16 of a block's work is accepted.
  2. Remove `ref` and `REF_WINDOW`, the six following headers and the floor's schedule (the last two the user's own
     choice for review 1's finding 6): an anchor is its proof and its block's one header, against one compiled floor.
  3. *Decision 12*: replace N5a's tiers by a dissent message, which shows a first lookup's name id to every server in
     the room and to a relay that knows the room's ID. Without it, N5a stays as built.
  4. Whether the loops this takes (R1 records, R2 servers and explorers with finding 3, R3 dissent) run before N6
     (recommended) or as the planned loop at the end.
